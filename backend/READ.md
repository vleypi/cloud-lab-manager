# Правила работы команды (бэкенд)

Срок маленький, делать много, поэтому правила короткие, но соблюдаем их все,
чтобы не терять время на фикс багов. Источник правды по задачам это ТЗ +
таблица распределения. Стэк фреймворка втроём решаете сами, типа FastAPI и тд.
Можете от себя что-то тут напсиать, испарвилить или добавить. По  сути я напсиал +- базу
но тк за бекенд сразу 3 челвоека овтечает, вы должны еще какие-то детали между собой обсудить если оно того требует.

## Репозиторий

Я создаю репо с двумя папками - Frontend (моя) и Backend (ваша). На корне
будет лежать docker-compose и .gitognore, в Backend свой README + .env.example (не .env, не .env.local, 
а .env.example, чтобы вы не запутались в свои переменых окружения). 
Код в Backend не валим в один файл, бьём по смыслу: эндпоинты отдельно, бизнес-логика отдельно,
работа с БД отдельно, обёртки над КИ/Moodle отдельно. Эндпоинт не лезет
напрямую в базу или в OpenStack - только через слой логики. Это прям по
Критерию 7 (архитектура).

## Git

Как работаем: подтянул свежий main -> создал от него свою локальную ветку под свою задачу ->
работаешь только в своей ветке -> перед pull request подтянул main к себе и решил
конфликты локально -> запушил ветку

Ветки называем по смыслу задачи, латиницей через дефис: feat/pool-manager,
fix/ssh-keys, refactor/state-machine. Без транслита и пробелов.

Не забываем про .gitignore файл в корне!! 

## Коммиты

В файле COMMIT_CONVENTION.md все правила правильных коммитов на гитхаб.

## Имена и комментарии

Обязателньо комменатрием функции или endpoints, чтобы все друг дурга понмиания сразу.
Имена должны объяснять смысл. Не `c = connect()`, а
`connection = connect()`. Функции — глаголом (get_free_project, deploy_vm).
Булевы — is_/has_ (is_frozen)  и тд.

## README + Swagger (обязательно, оценивается)

В README по Backend: как поднять локально и через docker-compose, какие нужны
переменные окружения, список эндпоинтов или ссылка на Swagger, пара слов про
архитектуру. Каждый новый эндпоинт сразу попадает в Swagger.

## Безопасность

Никаких паролей и токенов в коде. Всё в .env / переменные окружения. В репо
только .env.example с пустыми значениями, сам .env в .gitignore - проверьте это
до первого коммита. Доступ к КИ по нативным SSH-ключам, статические пароли в
конфигах запрещены по ТЗ.
